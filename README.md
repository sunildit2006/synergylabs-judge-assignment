# LLM-as-Judge Evaluation Pipeline

A pairwise A-vs-B judging pipeline with concrete, code-level bias mitigations for the
five biases named in the assignment.

## Judging mode

**Pairwise A-vs-B**, chosen because it directly supports the assignment's core deliverable
(a position-bias check with a measured flip rate) and because comparing two concrete
outputs is a more stable signal than an absolute 1-5 pointwise score, which tends to
cluster.

## Setup

pip install -r requirements.txt
cp .env.example .env
# add your GEMINI_API_KEY (free: https://aistudio.google.com/apikey)

## Run

python main.py

## Bias handling

| Bias | Where it's mitigated | How it's measured |
|---|---|---|
| Position (A/B order) | mitigations.evaluate_pairwise_unbiased runs every case in both orders | position_flip_rate in the suite report |
| Verbosity/length | Rubric penalizes unsupported fluff; verbosity probes pair short-correct vs padded | Adversarial probe pass rate |
| Self-enhancement | Judge is Gemini; test-suite outputs are pre-written static text, not generated live by the judge | Documented by construction |
| Sycophancy/style | Prompt forces per-criterion rationale before the score; sycophancy probes test confident-but-wrong vs plain-correct | Adversarial probe pass rate |
| Score clustering | Few-shot anchor examples (1, 3, 5 point examples) embedded in the judge prompt | Manual inspection of score spread in logs |

## Results (actual run)

- 5 pairwise cases, both orders (10 judge calls) + 4 adversarial probes = 14 total judge calls
- Judge model: gemini-3.6-flash
- A/B result: Config A won 80% of cases, B won 0%, 20% ties -- A declared overall winner
- Position flip rate: 0.2 (1 of 5 cases changed winner when order was swapped)
- Gold-label agreement: 100% exact match, Cohen's kappa = 1.0 (n=5)
- Adversarial probe pass rate: 100% (4/4) -- not fooled by verbosity or sycophancy probes

## Discussion

Full run: 5 pairwise cases (10 judge calls, both orders) + 4 adversarial probes (4 calls)
= 14 total judge calls, judge model gemini-3.6-flash.

**A/B result:** Config A won 80% of cases, B won 0%, 20% ties. Config A declared overall
winner.

**Position bias:** flip rate was 20% (1 of 5 cases changed its declared winner when
response order was swapped) -- this is the number that matters most: it means roughly
1 in 5 single-order judgments in this run would have been an artifact of ordering rather
than genuine quality difference, if we hadn't run both orders and caught it.

**Gold-label agreement:** 100% exact match, Cohen's kappa = 1.0 against the 5
human-labeled cases -- strong agreement, though the sample size (5) is small enough that
this should be read as promising, not conclusive.

**Adversarial probes:** 100% pass rate (4/4) -- the judge was not fooled by either the
padded-verbose-but-not-better probe or the confidently-worded-but-wrong probe.

**Would this gate a release?** With a 20% position flip rate on only 5 cases, not yet as
the sole gate -- that flip rate needs to come down (or be explained) on a larger sample
before trusting it unsupervised. The adversarial and gold-label results are strong enough
to use as one signal alongside human spot-checks, not as a fully automated gate on its
own yet.

## Known simplifications
- Only pairwise mode is implemented (assignment requires at least one).
- Self-enhancement mitigation is satisfied by construction (static test outputs, not
  live-generated by the judge) rather than two live different-family APIs.
- Test-retest consistency function exists in validator.py but wasn't run in this
  session, to conserve free-tier API quota.
